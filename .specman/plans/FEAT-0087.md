## AC-1/AC-2 — modal creation flows with local errors

Replace both hidden inline create forms with one reusable modal shell whose mode
(extension or file) controls its title, label, placeholder, and submit callback.
Opening focuses an empty input; Escape, Cancel, or the backdrop dismisses it.
Validation/storage failures render in the modal alert and keep the user's value
available for correction. A successful create closes the modal and selects the
new extension or opens the new file. Add discriminating DOM-contract and browser
tests before changing the markup and handlers.

Files: `workbench.html`, `src/workbench-main.ts`, `src/styles.css`,
`src/workbench.test.ts`, `e2e/extensions.spec.ts`.

## AC-3 — guarded file writes remain unchanged

Keep the current last-seen mtime passed to `writeScriptFile`; tab work must not
share or overwrite mtimes across file paths. Existing storage tests remain the
regression boundary.

Files: `src/workbench-main.ts`, `src/script-storage.test.ts`.

## AC-4 — remove duplicate extension management

Remove the workbench's Extension options section and its rename/delete/enable
controls and handlers. Extension enablement and removal continue through the
existing manager in the notes window; the workbench remains an authoring
surface.

Files: `workbench.html`, `src/workbench-main.ts`, `src/styles.css`,
`src/workbench.test.ts`, `e2e/extensions.spec.ts`, `docs/extensions.md`.

## AC-5/AC-6 — diagnostics and explicit enablement boundary

Keep non-create diagnostics in the workbench diagnostic surface and do not add
runtime activation to create/save. Creation-specific errors stay prominent in
the modal. Update browser assertions to confirm newly created extensions are
not presented as enabled by the workbench.

Files: `src/workbench-main.ts`, `e2e/extensions.spec.ts`.
