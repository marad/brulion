## AC-1 (added): Given an existing markdown target relative to `from`, when
  `resolveLink(target, {kind: "markdown", from})` is called, then it returns
  `status: "resolved"` with the canonical `.md` path and the fragment without
  `#`.

Approach: Split the raw markdown destination at the first anchor, normalize the source path, resolve relative POSIX segments with `resolveNotePath`, normalize the resulting note path, and classify it against the adapter's fresh path set.

Files:
- `src/extension-navigation.ts`
- `src/extension-navigation-resolver.test.ts`
- `src/extension-navigation-adapter.ts`

## AC-2 (added): Given `#section` and a valid source note, when it is resolved as
  markdown, then it returns the source note path with the anchor; given a
  relative path that stays inside the vault but is absent, then it returns
  `status: "missing"` with that canonical path rather than creating it.

Approach: Treat a non-empty `#anchor` with no path as a same-note target requiring a valid explicit or active source; return resolved or missing according to the fresh listing, and never create or switch.

Files:
- `src/extension-navigation.ts`
- `src/extension-navigation-resolver.test.ts`

## AC-3 (added): Given an HTTP(S), protocol-relative, or other scheme URL, when it is
  resolved as markdown, then it returns `status: "external"` with the original
  destination and does not consult or mutate the note listing.

Approach: Classify scheme and protocol-relative destinations before anchor splitting or source validation, returning the original target and avoiding any note-path lookup.

Files:
- `src/extension-navigation.ts`
- `src/extension-navigation-resolver.test.ts`

## AC-4 (added): Given a markdown destination that escapes the root, has an unsafe path,
  lacks the required note form, or has no usable source for a relative/same-note
  target, when it is resolved, then it returns `status: "invalid"` and no
  filesystem or active-view operation is performed.

Approach: Return invalid for unsupported syntax, missing source context, root-escaping or absolute paths, unsafe segments, empty targets, and non-markdown destinations; reuse `normalizeNoteName` as the final safety gate.

Files:
- `src/extension-navigation.ts`
- `src/extension-navigation-resolver.test.ts`

## AC-5 (added): Given a wikilink bare basename matching an existing note, a slashed
  root-relative target, or a case-insensitive match, when it is resolved, then
  it returns the same canonical path Brulion's editor resolver uses; duplicate
  basenames use the authoritative sorted-list first match.

Approach: Normalize the wikilink destination, delegate matching and duplicate-basename ordering to `resolveWikilink` with the authoritative sorted set, then canonicalize the returned path.

Files:
- `src/extension-navigation.ts`
- `src/extension-navigation-resolver.test.ts`

## AC-6 (added): Given a valid but absent wikilink with or without a slash, when it is
  resolved, then it returns `status: "missing"` with the normalized root or
  slashed `.md` path; no file is created and aliases are not interpreted.

Approach: Use the normalized `resolveWikilink` create path for valid absent bare or slashed targets, preserving only the anchor and never calling a mutation API.

Files:
- `src/extension-navigation.ts`
- `src/extension-navigation-resolver.test.ts`

## AC-7 (added): Given an empty, unsafe, traversal, malformed-kind, or otherwise invalid
  wikilink destination, when it is resolved, then it returns `status: "invalid"`
  rather than a createable path; external-looking targets are classified by the
  documented external-link rule.

Approach: Reject empty/anchorless, traversal, unsafe, reserved, non-note, and unsupported-kind inputs before matching; classify external schemes using the shared external-link predicate.

  bytes remain unchanged.

Approach: Keep the resolver pure: read only the supplied immutable context, return detached result objects, and add repeated-call tests that assert the note-path set and active path are unchanged.
