# Sync plan — FEAT-0113 Loss-aware serialization and note-controller integration

Started: 2026-08-14T15:20:56.547Z
Snapshot state: new
Drift summary: 10 added (whole spec)

## AC-1 (added): Rich primary load boundary

Approach: Add a CodeMirror rich-editor transaction layer that stores the imported
`RichDocument` in a state field while CodeMirror holds only its visible
projection. Programmatic source loads import once, replace the visible document,
and annotate the transaction so autosave/history consumers do not treat it as a
user edit. Keep a raw-editor fallback for secondary editors and existing callers.

Files:
- `src/rich-editor.ts` — rich state field, visible-edit transaction filter, source
  load/reload and visible/source caret helpers.
- `src/editor-document.ts` — the primary editor document boundary with a raw
  fallback; exposes serialized Markdown, visible text, model, load, and reload.
- `src/editor.ts` — opt the primary mount into the rich extension and route text
  loads/selection reads through the boundary without changing raw editor mounts.
- `src/rich-editor.test.ts`, `src/editor-document.test.ts`, `src/editor.test.ts` —
  projection, programmatic-load, and raw-fallback coverage.

## AC-2 (added): Visible editing and serialized snapshots

Approach: Apply CodeMirror visible changes to `RichDocument` before the
transaction is committed, then replace the interim text with the model's visible
projection in the same transaction. Use the existing loss-aware model for
completed/incomplete inline and block input; map the final visible selection from
the interim change so conversion is one history unit. Preserve explicit P4 raw
islands as source-editable only through the editor boundary.

Files:
- `src/rich-editor.ts` — transaction filtering and visible selection mapping.
- `src/rich-markdown.ts` — a boundary-only visible-range replacement helper for
  cross-fragment/raw-island editor edits.
- `src/rich-editor.test.ts`, `src/rich-markdown.test.ts` — typing, conversion,
  incomplete markers, cross-fragment, and history regressions.

## AC-3 (added): Byte-fidelity import/serialization

Approach: Keep the rich state field's source as the authoritative snapshot and
never serialize from the visible CodeMirror document. Source-only unchanged loads
return the original string; visible edits reproject from the loss-aware source
and retain opaque/special nodes and line endings. Add representative Unicode,
CRLF, nested, link, fence, table, frontmatter, Mermaid, and unknown-source tests.

Files:
- `src/rich-editor.ts`, `src/editor-document.ts` — source snapshot boundary.
- `src/rich-editor.test.ts`, `src/editor-document.test.ts` — exact round-trip and
  intended-span evidence.

## AC-4 (added): Save/autosave/lazy creation

Approach: Give `NoteController` an `EditorDocumentBoundary` and replace every
primary-content read with `readMarkdown()`. Track `savedMarkdown` separately from
the visible document; recompute dirty from serialized source on edits, capture one
source snapshot per guarded save, and update the cache/list only after `saveNote`
succeeds. Raw views use the adapter fallback, so existing controller unit seams
remain valid.

Files:
- `src/note-controller.ts` — serialized dirty/save/cache integration.
- `src/note-controller.test.ts` — rich-visible/source divergence, autosave,
  flush, lazy materialization, and mtime arguments.

## AC-5 (added): Switching and mutation integration

Approach: Route load, preview/revert, activate, switch, create, rename/move
follow-up, and conflict resolution through the document boundary. Keep link
maintenance and note storage on raw Markdown strings; never pair a destination
path or mtime with the previous model. The raw fallback preserves secondary test
and controller callers while the primary path is rich.

Files:
- `src/note-controller.ts`, `src/main.ts` — boundary wiring and rich primary mount.
- `src/note-controller.test.ts`, `src/main` integration coverage where existing
  seams permit.

## AC-6 (added): External refresh and position preservation

Approach: Reload the external source by importing a new model and computing a
visible diff. Map the old visible selection and viewport anchor through the old
source → source diff → new model visible mapping; dispatch a programmatic rich
reload with no autosave callback. Adopt the new raw source/mtime only after the
safe-to-replace check passes.

Files:
- `src/rich-editor.ts`, `src/editor-document.ts`, `src/editor.ts` — reparse and
  selection/viewport mapping.
- `src/rich-editor.test.ts`, `src/editor.test.ts`, `src/note-controller.test.ts` —
  clean refresh, source-only formatting changes, caret/viewport, and no dirty mark.

## AC-7 (added): Serialized conflict handling

Approach: Compare `savedMarkdown` to `readMarkdown()` for dirtiness and capture
serialized `mine` for conflict UI. Keep the existing modal and stale-write guard,
but make keep-mine, take-theirs, deletion, and re-created lazy notes use the
boundary's source load/read methods. Do not clear conflict/dirty state until the
serialized guarded operation succeeds.

Files:
- `src/note-controller.ts` — conflict source snapshots and resolution.
- `src/note-controller.test.ts` — rich conflict versions, keep/take, deletion,
  and stale-write regressions.

## AC-8 (added): Raw-source API boundary

Approach: Expose source snapshots and source-coordinate selection helpers from the
editor boundary. Update the main extension adapter to use serialized Markdown and
translate M46 source selections through the rich source map; normal visible edits
still go through the rich transaction filter. Explicit P4 source edits remain
model-owned and stale guarded.

Files:
- `src/editor-document.ts`, `src/editor.ts`, `src/main.ts` — raw source reads and
  UTF-16 source/visible selection translation.
- `src/editor-document.test.ts`, `src/editor.test.ts` — source API positions and
  hidden-boundary behavior.

## AC-9 (added): Secondary editors stay raw

Approach: Make rich mode opt-in on `mountEditor`; workbench, merge view, script
editor, and all raw EditorState adapters retain their current document contract.

Files:
- `src/editor.ts`, `src/editor.test.ts`, `src/workbench.test.ts` — rich opt-in and
  raw-secondary regression coverage.

## AC-10 (added): Failure atomicity and stale state

Approach: Keep the prior model when visible projection or mapping rejects an
operation, and let controller writes proceed only from a captured serialized
snapshot with the existing mtime guard. A failed source load/reload leaves the
previous valid model/editor and dirty/conflict state intact; failed saves leave
those states dirty/standing.

Files:
- `src/rich-editor.ts`, `src/editor-document.ts`, `src/note-controller.ts` —
  guarded source/model transitions.
- `src/rich-editor.test.ts`, `src/note-controller.test.ts` — invalid mapping,
  failed load/reparse, and stale-write tests.
