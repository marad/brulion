# Sync plan — FEAT-0114 Rich editor selection, clipboard, commands, Vim, and extension compatibility

Started: 2026-08-14T20:18:21.172Z
Snapshot state: new
Drift summary: 10 added (whole spec)

## AC-1 (added): Given a loaded rich document containing headings, nested inline marks,
  quotes, lists, links, and Unicode, when it is displayed, then the CodeMirror
  projection styles the corresponding visible spans and block lines, link spans
  expose the existing navigation metadata, and no Markdown delimiter/prefix is
  present as a visible or atomic caret range.

Approach: Add a model-driven rich rendering adapter that maps `RichDocument.ranges`
from UTF-16 model-visible offsets to CodeMirror's LF-visible offsets, applies the
existing heading/mark/link classes and link attributes, and installs no hidden or
atomic source decorations. Keep raw Markdown rendering on raw editor mounts.

Files:
- `src/rich-render.ts` and `src/rich-render.test.ts`
- `src/rich-editor.ts` (export visible-position conversion used by adapters)
- `src/editor.ts` and `src/editor.test.ts`

## AC-2 (added): Given a non-empty visible selection, when Bold, Italic, Code, Heading,
  or Clear formatting is invoked from the selection toolbar, keyboard command,
  or slash command, then the rich model performs the operation at visible
  positions, the resulting serialized Markdown retains unrelated source bytes,
  and the complete action is one undo/history unit. Invalid, cross-opaque, or
  unsupported selections are rejected without a partial write.

Approach: Extend the pure rich model with source-preserving heading and clear-format
operations, expose one rich dispatch helper that commits model/visible text and
selection in one transaction, and route the shared format surfaces through rich
operations only when the primary state carries the rich field. Preserve raw
EditorState transforms for secondary editors.

Files:
- `src/rich-markdown.ts` and `src/rich-markdown.test.ts`
- `src/rich-editor.ts` and `src/rich-editor.test.ts`
- `src/format-actions.ts`, `src/markdown-commands.ts`, `src/slash-commands.ts`,
  `src/selection-toolbar.ts`, `src/context-menu.ts`
- corresponding command/action/editor tests

## AC-3 (added): Given a visible selection that starts or ends inside a formatted span,
  block prefix, or link label, when the user copies it, then the clipboard's
  `text/plain` value is valid Markdown containing only the selected content plus
  the minimum boundary syntax needed to preserve the formatting/link meaning.
  Imported delimiters and source line endings are retained when determinable;
  empty selections produce no custom clipboard payload.

Approach: Add a pure rich selection serializer driven by source-map ranges, block
prefixes, link nodes, and original delimiter bytes. Make the existing copy handler
select the rich serializer for rich states and retain its raw syntax-tree path for
raw states. Add discriminating nested/partial/link/Unicode/CRLF/multi-range tests.

Files:
- `src/copy-markdown.ts` and `src/copy-markdown.test.ts`
- `src/rich-markdown.ts`/`src/rich-editor.ts` only for mapping helpers

## AC-4 (added): Given a non-empty visible selection, when the user cuts it, then exactly
  the selected visible content is removed, the rich projection and serialized
  source remain synchronized, complete empty formatting wrappers are removed,
  and undo restores both the visible selection content and its original source
  spelling. A raw/opaque special block is never rewritten by ordinary cut.

Approach: Route rich cut through a single rich visible replacement transaction,
with deletion cleanup for wrappers whose entire visible content was selected and
safe rejection for opaque/special spans. Reuse the rich serializer for the
clipboard payload and keep raw cut behavior unchanged.

Files:
- `src/rich-editor.ts`, `src/rich-markdown.ts`, `src/copy-markdown.ts`
- `src/rich-editor.test.ts`, `src/copy-markdown.test.ts`

## AC-5 (added): Given plain-text Markdown or text copied from the rich editor on the
  clipboard, when it is pasted into a rich selection, then the text enters via
  the visible rich-edit boundary, complete markers are flushed at the paste
  boundary, one paste is one undo unit, and HTML clipboard data is ignored.
  Existing rich marks and opaque/special source outside the pasted range remain
  unchanged.

Approach: Add a rich paste transaction helper that applies the replacement and
EOF-flushes pending Markdown before one model/visible dispatch. Install a
text/plain-only DOM paste handler for rich views; unavailable clipboard data
falls through without an unhandled error. Raw views retain CodeMirror paste.

Files:
- `src/rich-editor.ts`, `src/copy-markdown.ts`, `src/editor.ts`
- `src/rich-editor.test.ts`, `src/copy-markdown.test.ts`, `src/editor.test.ts`

## AC-6 (added): Given a rich editor with a visible line, when the user opens the slash
  menu or types `[[` and accepts a heading/clear command or an existing-note
  wikilink, then the command replaces only its visible token/range, closes the
  completion, and the resulting rich/source projection is immediately usable
  without raw Markdown offsets or duplicate `]]` delimiters.

Approach: Expose completion sources as direct CodeMirror overrides for rich mounts,
make slash acceptance perform a rich model command after removing only its visible
token in the same dispatch, and make wikilink acceptance insert through the rich
visible boundary. Keep the existing Markdown-language completion registration for
raw mounts.

Files:
- `src/slash-commands.ts`, `src/link-complete.ts`, `src/rich-editor.ts`, `src/editor.ts`
- `src/slash-commands.test.ts`, `src/link-complete.test.ts`, `src/rich-editor.test.ts`

## AC-7 (added): Given serialized Markdown with duplicate, Unicode, or CRLF headings,
  when a local link/extension requests a heading anchor, then the first matching
  heading is selected and scrolled using visible positions, the caret lands on
  visible heading content rather than a hidden prefix, and a missing anchor is a
  no-op.

Approach: Keep the existing serialized-source heading scan as the single resolver,
strengthen its rich source-to-editor mapping tests for duplicate headings,
Unicode, CRLF, and source prefixes, and ensure rich rendering styles the mapped
heading without exposing its prefix.

Files:
- `src/editor.ts`, `src/editor.test.ts`, `src/rich-editor.test.ts`

## AC-8 (added): Given Vim mode enabled on the primary rich editor, when the user moves,
  selects, yanks, deletes, or pastes, then motions and selections use visible
  projection offsets, yank uses the same boundary-fidelity Markdown as browser
  copy, and hidden delimiters are never normal motion targets. The legacy hidden
  syntax guard is absent from rich mode; explicit opaque/source edits remain
  outside normal Vim motions and are covered as a documented limitation.

Approach: Gate the legacy hidden-range caret guard to raw mounts, make the common
Vim yank serializer rich-state aware, and rely on the rich transaction filter for
visible Vim edits/pastes. Add tests for visible motions, rich yank/copy parity,
reverse selections, and the explicit source-island limitation.

Files:
- `src/editor.ts`, `src/vim-caret.ts`, `src/vim-yank.ts`, `src/copy-markdown.ts`
- `src/vim-caret.test.ts`, `src/editor.test.ts`, `src/copy-markdown.test.ts`

## AC-9 (added): Given an extension reading or setting the primary editor selection, when
  the rich document contains hidden Markdown syntax, reverse selections, Unicode,
  or CRLF, then `getText` and selection `anchor`/`head`/`text` remain serialized
  Markdown and UTF-16 source-compatible, `setSelection` maps through the source
  map, and `replaceSelection` mutates only the intended rich/source span. Raw
  secondary editors retain their existing direct CodeMirror behavior.

Approach: Preserve the existing editor-document source facade and public selection
shape, add regression tests through the real rich mount and extension capability
adapter, and reject stale/out-of-bounds source requests before dispatch. Do not
route workbench, script, or conflict-diff mounts through rich extensions.

Files:
- `src/editor.ts`, `src/editor-document.ts`, `src/main.ts`
- `src/rich-editor.test.ts`, `src/editor.test.ts`, `src/extension-host.test.ts`

## AC-10 (added): Given an invalid/stale rich selection, unavailable clipboard, malformed
  completion token, or unsupported opaque edit, when the adapter handles the
  request, then it returns/falls through without throwing an unhandled DOM error,
  does not partially dispatch, and leaves the prior model, serialized source,
  dirty state, and conflict state intact.

Approach: Centralize rich adapter validation before dispatch, use null/false
fall-through contracts for browser handlers, and test failed model operations
against exact source/model snapshots. Keep controller dirty/conflict ownership in
P5 and avoid adding a second persistence or error state.

Files:
