## AC-1 (added): Given a checkout with one open milestone ledger, when CI or pre-push
  runs without `--milestone`, then it selects that milestone; when all ledgers
  are closed it selects the latest numbered milestone; when more than one is
  open it fails closed and names each candidate; an explicit path still wins.

Approach: Add a shared milestone-ledger resolver that selects exactly one open
milestone, falls back to the highest numbered closed milestone for final
shipping, and reports ambiguity rather than guessing. Thread the resolved path
through the existing full-gate runner while keeping an explicit `--milestone`
override. Remove the historical M45 default from both GitHub workflows.

## AC-4 (added): Given an exact base commit and spec id, when the read-only pre-review
