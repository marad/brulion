# Sync plan — FEAT-0090 Workbench freshness and release validation

SpecMan sync was blocked by the intentionally uncommitted M39 base in this
read-only-git worktree. This plan records the phase-first implementation
contract before code changes.

## AC-1/AC-2 — refresh and conflict

Refresh the workbench on attach/open/focus and on a bounded polling cadence;
reread current filesystem state before rendering or saving and surface mtime
conflicts without overwriting disk bytes.

Files: src/workbench.ts, src/workbench-main.ts, src/script-storage.ts,
src/workbench.test.ts.

## AC-3 — isolated reload

Reload only explicitly enabled extensions after a successful save and keep
failures in diagnostics without taking down notes or other runners.

Files: src/extension-registry.ts, src/workbench.ts, src/workbench-main.ts,
src/extension-registry.test.ts.

## AC-4 — portable fallback

Use ordinary polling/rescans as the baseline and leave FileSystemObserver out of
the correctness path until M40.

Files: src/workbench.ts, src/workbench.test.ts.

## AC-5 — browser release path

Add Chromium coverage for separate-window attach, scaffold creation,
multi-file editing, explicit enablement, command execution, and external-edit
conflict handling.

Files: e2e/extensions.spec.ts, workbench.html, src/workbench-main.ts.

## Verification

- `specman validate --strict`
- `npm test -- --run`
- `npm run build`
- `npm run e2e -- e2e/extensions.spec.ts --project=chromium`
- `git diff --check`
