# Sync plan — FEAT-0092 Extension active-note navigation

Started: 2026-08-11T09:39:50.533Z
Snapshot state: new
Drift summary: 8 added (whole spec)

## AC-1 (added): Given an attached vault with an active note, when an extension with
  `navigation:read` calls `getActiveNote`, then it receives only the canonical
  folder-relative `.md` path; when no note is active, it receives `null`.

Approach: Bind `getActiveNote` in the application adapter to the live controller/UI active path and return a detached canonical value, with a vault-generation guard before every callback.

Files:
- `src/main.ts`
- `src/extension-navigation.ts`
- `e2e/extension-navigation.spec.ts`

## AC-2 (added): Given a target file exists on disk but is absent from the current note
  list snapshot, when `openNote(target)` is called with `navigation:write`, then
  it opens that file, refreshes the authoritative list/sidebar, and returns
  `status: "opened"` rather than `missing` or creating another file.

Approach: Add a serialized controller operation that stats/reads the requested path directly, flushes the current note only after the target is confirmed, rereads the target, refreshes `listNotes`, and activates it through the existing load/announce path.

Files:
- `src/note-controller.ts`
- `src/extension-navigation-controller.test.ts`
- `e2e/extension-navigation.spec.ts`

## AC-3 (added): Given a target is absent on disk, when `openNote(target)` is called,
  then it returns `{status: "missing", path: target}` without creating the file,
  changing the active editor, changing the route, or changing recency.

Approach: Treat a null `statNote` result as a non-mutating discriminated result before any flush, list refresh, activation, or create call.

Files:
- `src/note-controller.ts`
- `src/extension-navigation-controller.test.ts`
- `e2e/extension-navigation.spec.ts`

## AC-4 (added): Given the requested target is already active and exists on disk, when
  `openNote(target)` is called, then it returns `status: "already-open"`, does
  not flush or push a duplicate history entry, and still reports the requested
  anchor status if an anchor was supplied.

Approach: Return an already-open controller result after the live existence check; let the application adapter perform the optional heading scan against the already-loaded editor without invoking a switch.

Files:
- `src/note-controller.ts`
- `src/main.ts`
- `src/extension-navigation-controller.test.ts`

## AC-5 (added): Given the active note has pending edits and a target file exists, when
  `openNote(target)` is called, then the current buffer is flushed through the
  normal mtime guard before switching; if the on-disk mtime conflicts, the
  result is `status: "conflict"` with the active path and neither note switch
  nor silent overwrite occurs.

Approach: Reuse `flushAndWait` inside the controller's serialize slot and inspect the existing conflict flag after it settles. Do not add a second save path or bypass `raiseConflict`.

Files:
- `src/note-controller.ts`
- `src/extension-navigation-controller.test.ts`
- `e2e/extension-navigation.spec.ts`

## AC-6 (added): Given two navigation requests arrive concurrently, when they target
  different existing notes, then the controller serializes them so the final
  editor, active row, saved active path, route, and mtime state all describe one
  completed operation rather than an interleaving.

Approach: Route the entire target revalidation/flush/list/activate transaction through the controller's existing serialize queue and preserve the existing `activate` announcement, recency, and route adapters.

Files:
- `src/note-controller.ts`
- `src/extension-navigation-controller.test.ts`

## AC-7 (added): Given a successful open with no anchor, with a matching heading slug, or
  with no matching heading, when the result is returned, then `anchorStatus` is
  respectively `not-requested`, `found`, or `not-found`; heading lookup skips
  fenced-code content and does not write the note.

Approach: Map controller opened/already-open results in the application adapter, call the existing `scrollEditorToHeading` only for a supplied anchor, and return its boolean as found/not-found without touching the document.

Files:
- `src/main.ts`
- `src/editor.ts`

## AC-8 (added): Given an open or navigation operation is in progress and the vault is
  switched or detached, when an old callback completes, then it cannot mutate
  the newly attached vault or active editor and fails closed as an unavailable
  capability.

Approach: Close each injected navigation callback over the exact directory handle and generation used by `reloadExtensions`, assert it is still current before and after asynchronous controller/listing work, and rely on registry disposal during vault changes.

Files:
