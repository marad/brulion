# Sync plan — FEAT-0111 Block input rules and rich block editing

Started: 2026-08-14T07:14:20.263Z
Snapshot state: new
Drift summary: 7 added (whole spec)

## AC-1 (added): Given a visible line ending in a completed `# ` through `###### ` prefix,
  when the heading boundary is applied, then the prefix becomes heading block
  metadata, the visible content starts after the hidden prefix, the caret maps
  to the visible content start, and serialization retains the original prefix
  bytes until that block is edited.

Approach: Add a pure block-boundary classifier and apply operation over the existing loss-aware import model. Recognize only a complete heading prefix at the current line boundary, reproject the same source without exposing the prefix, and return the mapped visible caret.

Files:
- `src/rich-markdown.ts` — block boundary types, classifier, and application operation.
- `src/rich-markdown.test.ts` — heading boundary/caret/source regression tests.

## AC-2 (added): Given a visible line ending in `> `, `* `, or `- `,
  when the block boundary is applied, then it becomes the corresponding quote or
  unordered-list block, incomplete or prefix-like text without boundary
  whitespace remains literal, and UTF-16 source/visible mappings remain
  deterministic.

Approach: Extend the same classifier with quote and unordered-list prefixes, preserving the existing lineBlock/source-map contract and rejecting incomplete or unsupported prefix-like text.

Files:
- `src/rich-markdown.ts` — quote/list boundary classification.
- `src/rich-markdown.test.ts` — boundary and UTF-16 mapping tests.

## AC-3 (added): Given a non-empty quote or unordered-list item,
  when Enter is applied, then a new line continues the same block with the
  canonical continuation prefix and the caret lands at its visible content
  start; given an empty item, when Enter is applied, then the new line exits to
  a plain paragraph without leaving a hidden prefix caret stop.

Approach: Add one visible block Enter operation that inspects the mapped line, inserts only the continuation source prefix for non-empty quote/list blocks, and inserts a newline without a prefix for empty blocks. Return the resulting rich document and visible caret.

Files:
- `src/rich-markdown.ts` — Enter block edit operation.
- `src/rich-markdown.test.ts` — continuation, empty-item exit, and caret tests.

## AC-4 (added): Given an empty heading, quote, or list block at its visible content
  start, when Backspace is applied, then the block prefix is removed or the
  block exits according to its construct rule, the visible text and caret remain
  valid, and unrelated source spans are unchanged.

Approach: Add a mapped Backspace operation with explicit empty-block rules: remove the heading/list/quote prefix and reimport the edited source, while refusing edits in opaque or non-empty content. Keep replacements limited to the selected block prefix.

Files:
- `src/rich-markdown.ts` — Backspace block edit operation.
- `src/rich-markdown.test.ts` — empty-block prefix removal and source-isolation tests.

## AC-5 (added): Given one or more selected blocks, when indentation or outdentation is
  applied, then only those blocks' prefixes change, nested quote/list structure
  remains representable, and serialization preserves all untouched bytes,
  including line endings and unrelated marker spelling.

Approach: Add a block-indent operation that maps visible selection to complete source lines, applies canonical one-level prefix changes only to supported quote/list lines, and returns source replacements plus mapped caret/selection positions. Reject opaque/ordered/unsupported lines rather than normalizing them.

Files:
- `src/rich-markdown.ts` — indentation/outdentation operation.
- `src/rich-markdown.test.ts` — multi-line selection, CRLF, nesting, and isolation tests.

## AC-6 (added): Given an imported ordered-list line or unknown block-like syntax,
  when block input/edit operations are applied elsewhere, then it remains an
  opaque/source-preserving region and is not silently renumbered, normalized, or
  converted into another block type.

Approach: Keep ordered-list and opaque lines outside mutation candidates; operations compute and apply only supported line replacements and use the existing source-authoritative serializer.

Files:
- `src/rich-markdown.ts` — candidate filtering and no-op/error results.
- `src/rich-markdown.test.ts` — ordered/opaque preservation tests.

## AC-7 (added): Given any block operation on Unicode content, CRLF input, nested inline
  marks, or an opaque neighboring line, when it is serialized and mapped, then
  UTF-16 positions, inline rich marks, opaque bytes, and visible caret placement
  remain correct; no operation inserts raw Markdown delimiters into the visible
  projection.

Approach: Reuse UTF-16 source/visible mapping helpers and import/reprojection after each bounded replacement. Add discriminating regression coverage for surrogate pairs, CRLF, nested inline marks, and neighboring opaque lines.

Files:
- `src/rich-markdown.ts` — mapping-safe block edits.
- `src/rich-markdown.test.ts` — fidelity and caret regression tests.
