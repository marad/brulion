# Sync plan — FEAT-0111 Block input rules and rich block editing

Started: 2026-08-14T09:04:28.067Z
Snapshot state: new
Drift summary: 8 added (whole spec)

## AC-1 (added): Given a visible line ending in a completed `# ` through `###### ` prefix,
  when the heading boundary is applied, then the prefix becomes heading block
  metadata, the visible content starts after the hidden prefix, the caret maps
  to the visible content start, and serialization retains the original prefix
  bytes until that block is edited.

Approach: Use a pure source-cursor block-prefix classifier and reproject the same source through the existing loss-aware importer; hidden heading prefixes remain source-mapped and the returned caret is converted through the UTF-16 map.

Files:
- `src/rich-markdown.ts` — block boundary types, classifier, and application operation.
- `src/rich-markdown.test.ts` — heading boundary/caret/source tests.

## AC-2 (added): Given a visible line ending in `> `, `* `, or `- `,
  when the block boundary is applied, then it becomes the corresponding quote or
  unordered-list block, incomplete or prefix-like text without boundary
  whitespace remains literal, and UTF-16 source/visible mappings remain
  deterministic.

Approach: Extend the classifier and existing lineBlock parser for quote/list prefixes, including indentation, without interpreting incomplete prefixes or unsupported syntax; parse block bodies before inline fallback so `* ` is not misclassified as italic syntax.

Files:
- `src/rich-markdown.ts` — quote/list boundary classification and block metadata.
- `src/rich-markdown.test.ts` — quote/list, incomplete, star-list, and mapping tests.

## AC-3 (added): Given a non-empty quote or unordered-list item,
  when Enter is applied, then a new line continues the same block with the
  canonical continuation prefix and the caret lands at its visible content
  start; given an empty item, when Enter is applied, then the new line exits to
  a plain paragraph without leaving a hidden prefix caret stop.

Approach: Resolve the current mapped source line, preserve the full suffix around an interior caret, use original line-ending bytes without duplicating an EOF terminator, keep inline spans intact at split edges, insert a canonical quote/list continuation only for non-empty items, and reimport while mapping the caret after the hidden prefix. Ordered-list Enter is ordinary source editing and never auto-continues.

Files:
- `src/rich-markdown.ts` — Enter block edit operation and safe inline split mapping.
- `src/rich-markdown.test.ts` — continuation, empty exit, inline-mark, ordered, suffix, and CRLF tests.

## AC-4 (added): Given an empty heading, quote, or unordered-list block at its visible content
  start, when Backspace is applied, then the block prefix is removed or the
  block exits according to its construct rule, the visible text and caret remain
  valid, and unrelated source spans are unchanged. Ordered-list prefixes remain
  source-preserving under Backspace.

Approach: Resolve only empty supported blocks at their mapped content start, remove exactly the hidden prefix source span, preserve transient rich projection state through the bounded replacement, and reject non-empty/opaque/ordered contexts without mutation.

Files:
- `src/rich-markdown.ts` — Backspace block edit operation.
- `src/rich-markdown.test.ts` — empty-prefix, ordered no-op, and no-op tests.

## AC-5 (added): Given one or more selected blocks, when indentation or outdentation is
  applied, then only those blocks' prefixes change, nested quote/list structure
  remains representable, and serialization preserves all untouched bytes,
  including line endings and unrelated marker spelling.

Approach: Map a non-collapsed visible selection to complete source lines, reject unsupported lines, apply two-space prefix replacements only to quote/list lines, preserve all line endings, map explicit adjacent markers through prefix replacements, and reimport the bounded source edit with the original visible selection.

Files:
- `src/rich-markdown.ts` — indentation/outdentation and transient-state mapping.
- `src/rich-markdown.test.ts` — multi-line, CRLF, nested, marked, and isolation tests.

## AC-6 (added): Given an imported ordered-list line or unknown block-like syntax,
  when any P3 block input/edit operation is applied to it or elsewhere, then it
  remains an opaque/source-preserving region and is not silently renumbered,
  normalized, continued, or converted into another block type.

Approach: Detect opaque source ranges before block operations and leave ordered/unknown lines outside the supported mutation set; return no-op/null instead of normalizing or continuing them.

Files:
- `src/rich-markdown.ts` — opaque/candidate filtering and ordered preservation.
- `src/rich-markdown.test.ts` — ordered and opaque preservation tests.

## AC-7 (added): Given any block operation on Unicode content, CRLF input, nested inline
  marks, or an opaque neighboring line, when it is serialized and mapped, then
  UTF-16 positions, inline rich marks, opaque bytes, and visible caret placement
  remain correct; no operation inserts raw Markdown delimiters into the visible
  projection.

Approach: Reuse sourceToVisible/visibleToSource and source-authoritative reimport for every operation; bounded replacement mapping preserves pending and explicit marker state, and tests cover Unicode, CRLF, nested inline markers, opaque neighbors, interior splits, and source round-trip.

Files:
- `src/rich-markdown.ts` — mapping-safe block edits.
- `src/rich-markdown.test.ts` — fidelity and caret regression tests.

## AC-8 (added): Given the existing raw CodeMirror heading shortcut/slash adapters, when

  editing; the rich model's heading metadata and mapping contracts remain the
  only P3 requirement.

Approach: Keep the legacy EditorState command adapters unchanged in P3, record the P6 boundary in the milestone/spec, and verify that P3's rich model exports block metadata without claiming command integration.

Files:
