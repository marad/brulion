# Sync plan — FEAT-0085 Separate-window extension workbench contract

## AC-1 (added): Given an attached vault, when the user invokes the extension workbench,
  then a separate browser window opens with the effective workspace reference.

Approach: The notes-window action computes the effective workspace name and opens
`workbench.html` with only `?ws=<name>`. The workbench entry point restores the
requested vault independently; no handle or note content crosses the window
boundary.

Files:
`src/main.ts`, `src/workbench.ts`, `src/workbench-main.ts`, `workbench.html`,
`src/vaults.ts`.

## AC-2 (added): Given a workbench window with a matching persisted vault and permission,
  when it loads, then it attaches independently and lists that vault's scripts
  without requiring the notes window to remain open.

Approach: `attachWorkbenchVault` resolves the persisted vault by the workspace
reference, verifies or requests permission for that exact handle, and returns a
local directory root. `workbench-main.ts` discovers scripts directly from that
root and does not depend on the opener window remaining alive.

Files:
`src/workbench.ts`, `src/workbench-main.ts`, `src/vaults.ts`,
`src/script-storage.ts`, `e2e/extensions.spec.ts`.

## AC-3 (added): Given a missing or denied vault permission, when the workbench loads, then
  it shows a clear permission/reselect action and never opens a different vault
  because the requested reference was unavailable.

Approach: Attachment returns typed missing-vault, denied-permission, or access
errors. The workbench renders its recovery state and folder-picker action while
preserving the requested reference; it never invokes the normal most-recent-vault
fallback for an explicit unavailable workspace.

Files:
`src/workbench.ts`, `src/workbench-main.ts`, `src/vaults.ts`, `workbench.html`,
`src/workbench.test.ts`.

## AC-4 (added): Given two open windows for one vault, when either window changes a
  filesystem-backed extension file, then correctness depends only on a later
  filesystem reread; no inter-window message is required or treated as
  authoritative.

Approach: Each window owns its attachment, workbench session, refresh generation,
and filesystem reads. Focus, explicit refresh, and the bounded timer reread the
shared vault; there is no window-to-window IPC path used for correctness.

Files:
`src/workbench-main.ts`, `src/script-storage.ts`, `src/workbench.test.ts`,
`e2e/extensions.spec.ts`, `docs/excavation/extension-workbench/01-architecture.md`.

## AC-5 (added): Given the workbench is closed and reopened or reloaded, then its selected
  script/file state is reconstructed from the filesystem and not from window
  memory.

Approach: The workbench keeps only transient selection and path-keyed drafts in
its own window. A new load attaches from the URL/persisted vault set, rereads
scripts and files, and rebuilds the selected state from current filesystem data.

Files:
`src/workbench-main.ts`, `src/workbench.ts`, `src/script-storage.ts`,
`src/workbench.test.ts`, `e2e/extensions.spec.ts`.
