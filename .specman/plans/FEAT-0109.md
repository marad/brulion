# Sync plan — FEAT-0109 Loss-aware import and visible rich projection

Started: 2026-08-13T17:36:21.782Z
Snapshot state: new
Drift summary: 6 added (whole spec)

## AC-1 (added): Given Markdown containing paragraphs, headings, bold, italic, inline code,
  blockquotes, unordered lists, ordered lists, nested marks, and multiline lines,
  when it is imported, then the visible projection omits only supported prefixes
  and delimiters and every projected fragment exposes its block and mark metadata.

Approach: Extend the dependency-free Markdown importer to emit typed block and
inline mark ranges, preserving nested marks and unsupported source as opaque
visible fragments. Keep all offsets in JavaScript UTF-16 units.

Files:
- `src/rich-markdown.ts`
- `src/rich-markdown.test.ts`

## AC-2 (added): Given source containing Unicode including astral characters, when it is
  imported, then visible-to-source and source-to-visible mappings use UTF-16
  offsets, are deterministic at starts, ends, and delimiter boundaries, and never
  expose a hidden delimiter as a visible caret stop.

Approach: Test deterministic mappings at Unicode, empty-document, delimiter, and
source/projection boundaries. Reject out-of-range positions without mutation.

Files:
- `src/rich-markdown.ts`
- `src/rich-markdown.test.ts`

## AC-3 (added): Given unknown, unmatched, or unsupported Markdown, when it is imported,
  then it remains visible in an opaque/raw region and is never silently removed or
  interpreted as a supported construct.

Approach: Treat unsupported links and marker-like text as opaque source ranges;
only syntax explicitly supported by P1 is hidden from the visible projection.

Files:
- `src/rich-markdown.ts`
- `src/rich-markdown.test.ts`

## AC-4 (added): Given any imported document that has not been edited, when it is
  serialized, then the result is byte-identical, including line endings, spacing,
  delimiter choice, and unknown source.

Approach: Retain the original source string and apply no changes until an
explicit mapped replacement is requested.

Files:
- `src/rich-markdown.ts`
- `src/rich-markdown.test.ts`

## AC-5 (added): Given a deliberate replacement of one visible mapped fragment, when it is
  serialized, then only that fragment's original source span is replaced and all
  unrelated spans (including opaque syntax) remain byte-identical.

Approach: Store replacements by original range and serialize from right to left,
leaving every unrelated source span byte-identical.

Files:
- `src/rich-markdown.ts`
- `src/rich-markdown.test.ts`

## AC-6 (added): Given an empty document or a position at a projection boundary, when a
  mapping is requested, then the result is deterministic and in bounds; invalid
  positions are rejected without mutating the document.

Approach: Define empty-document identity mappings and explicit bounds checks for
all position APIs.

Files:
- `src/rich-markdown.ts`
- `src/rich-markdown.test.ts`
