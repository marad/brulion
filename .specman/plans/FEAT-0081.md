# Sync plan — FEAT-0081 Extension sandbox and RPC spike

## AC-1 (added): Given a host and a script peer with the same one-time nonce, when the peer
  performs the handshake over a dedicated message port, then the host marks the
  peer ready and a registered capability can be called asynchronously with a
  JSON-like result.

Approach: Add a small transport-agnostic RPC peer that authenticates a dedicated
  `MessagePort` with a nonce, performs a hello/ready handshake, dispatches only
  registered methods, and returns JSON-like results. Keep the protocol independent
  from the production editor and note controller so this spike can be removed or
  replaced without changing existing UI code. Include a browser harness that loads
  an inline script in an iframe with `sandbox="allow-scripts"` and transfers one
  `MessageChannel` port.

Files: src/extension-rpc.ts, src/extension-rpc.test.ts,
public/spikes/extension-sandbox.html

## AC-2 (added): Given an unregistered method, a malformed envelope, or a request carrying a
  wrong nonce, when the message reaches the host, then it is rejected with a
  structured error and no capability handler runs.

Approach: Validate every inbound envelope before dispatch: exact protocol/version,
  nonce, request id, method, and JSON-like params. Respond with stable error codes
  for malformed, unauthorized, and unknown calls. Tests inject hostile raw messages
  through a fake port and assert both the error and the untouched handler spy.

Files: src/extension-rpc.ts, src/extension-rpc.test.ts

## AC-3 (added): Given a request or result containing a non-JSON value (including an object
  with a prototype/method such as a File System Access handle), when it crosses the
  boundary, then the RPC rejects it and never exposes a host-owned object or handle
  to the script.

Approach: Define a recursive JSON-like wire-value guard that accepts primitives,
  arrays, and plain records only; reject class instances, functions, symbols,
  undefined, cycles, and non-finite numbers. The host API accepts handlers returning
  only this value type, so File System Access handles and editor/DOM objects cannot
  be transferred accidentally. Document that handles stay in the host and are
  represented by opaque, intentionally scoped data if a later capability needs it.

Files: src/extension-rpc.ts, src/extension-rpc.test.ts,
docs/spikes/FEAT-0081-extension-sandbox.md

## AC-4 (added): Given an in-flight call whose peer never replies, when the configured
  timeout elapses or the peer is disposed, then the call rejects, listeners and
  pending state are released, and messages arriving afterward are ignored.

Approach: Track outbound requests by id, arm one timeout per request, and settle
  each entry exactly once. `dispose()` removes the message listener, rejects all
  pending calls with a disposed error, and makes subsequent `call()`/messages
  fail closed. Tests use fake transports and a short clock-driven timeout.

Files: src/extension-rpc.ts, src/extension-rpc.test.ts

## AC-5 (added): Given the static Vite/GitHub Pages deployment, when the spike is reviewed in
  Chromium, then its artifact records the required iframe/CSP policy, the fact that
  opaque-origin frames require `postMessage("*", …)` plus source/nonce checks, and
  the File System Access rule that handles remain host-only. The spike provides a
  runnable protocol test/harness and explicitly marks native picker and permission
  behavior as manual follow-up.

Approach: Add a static `/spikes/extension-sandbox.html` harness served by Vite's
  `public/` directory. It uses an iframe with no `allow-same-origin`, a nonce and
  transferred `MessageChannel`, and visibly reports handshake, successful
  capability call, rejected method, and timeout/dispose outcomes. Record deployment
  constraints and manual checks in the spike note and ADR: static GitHub Pages
  cannot set response CSP headers, so the production host needs a meta policy plus
  a server/header plan; `frame-src`/`connect-src` must be tightened for the chosen
  script source; source identity and nonce must be checked because opaque-origin
  messaging uses `"*"`; native picker/permission behavior remains manual.

Files: public/spikes/extension-sandbox.html,
docs/spikes/FEAT-0081-extension-sandbox.md, DECISIONS.md
