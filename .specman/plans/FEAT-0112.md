# Sync plan — FEAT-0112 Links, code fences, tables, frontmatter, and Mermaid

Started: 2026-08-14T10:54:07.598Z
Snapshot state: new
Drift summary: 9 added (whole spec)

## AC-1 (added): Links and UTF-16 projection

Approach: Add a pure special-node scanner that walks protected Markdown spans
before the existing inline/block parser. It emits exact UTF-16 source ranges for
complete Markdown links, wikilinks, and bare web URLs, plus exact opaque spans
for closed fences, tables, leading frontmatter, and Mermaid fences. Rich ranges
carry link metadata while the document exposes stable node lists for explicit
source editing.

Files:
- `src/rich-specials.ts` — special/link node types, protected-span scanner,
  fence/table/frontmatter recognizers, exact cell ranges.
- `src/rich-specials.test.ts` — recognizer and source-range contract tests.

## AC-2 (added): Link-aware projection and protected regions

Approach: Extend inline fragment projection to consume link label spans and bare
URL spans only outside protected special nodes. Keep link delimiters/targets as
non-visible ranges and preserve nested existing marks inside labels; incomplete
or ambiguous forms fall back to one opaque raw line.

Files:
- `src/rich-markdown.ts` — link-aware fragments, link metadata, protected
  special-block projection, UTF-16 mapping.
- `src/rich-markdown.test.ts` — visible link projection, nested labels, URL
  nodes, and protected-region regressions.

## AC-3 (added): Explicit source editing

Approach: Add explicit source-edit APIs at the rich-document boundary. Link
edits address only target/label ranges; table-cell edits accept a fresh exact
cell node; special edits replace an explicitly selected special-block span. A
raw source-position lookup and raw-edit escape hatch cover hidden targets and
malformed syntax. Reimport after each operation and reject stale/ambiguous/
cross-node requests so normal visible replacement cannot touch hidden syntax.

Files:
- `src/rich-markdown.ts` — `sourceEditRangeAt`, `editRichLink`, `editTableCell`,
  and guarded source replacement types/functions.
- `src/rich-markdown.test.ts` — target/label/cell/special edits and rejection
  cases.

## AC-4 (added): Fenced code

Approach: Recognize closed backtick/tilde fences with exact delimiter metadata
and keep the entire span opaque/source-visible. Do not parse inline Markdown in
the body. Expose a source-edit range for explicit fence edits; incomplete or
mismatched fences remain ordinary opaque text.

Files:
- `src/rich-specials.ts` — fence scan and metadata.
- `src/rich-markdown.ts` — fence-protected projection and source-edit routing.
- `src/rich-specials.test.ts` — delimiter, info-string, CRLF, nesting, and
  unclosed-fence cases.

## AC-5 (added): Tables

Approach: Detect a contiguous header/separator table with a lossless pipe
scanner that honors escaped pipes and preserves each cell's exact source
content boundaries. Store alignment as advisory metadata and edit only a
selected cell content span; never round-trip through trimmed cell arrays.

Files:
- `src/rich-specials.ts` — table rows/cells, escaped-pipe scanning, alignment
  metadata.
- `src/rich-markdown.ts` — table nodes and cell-edit integration.
- `src/rich-specials.test.ts` — valid/ambiguous tables, escaped pipes, uneven
  rows, and exact edits.

## AC-6 (added): Frontmatter

Approach: Detect only a leading, closed frontmatter range using exact delimiter
lines while retaining trailing spaces and line endings in the raw span. Mark it
opaque and expose an explicit expandable/source-edit range without interpreting
fields.

Files:
- `src/rich-specials.ts` — leading frontmatter scan.
- `src/rich-specials.test.ts` — leading, non-leading, unclosed, CRLF, and
  byte-preservation cases.

## AC-7 (added): Mermaid classification

Approach: Classify a closed fence with a case-insensitive trimmed `mermaid`
info string as Mermaid metadata while retaining the same full raw span and
source-edit path as other fences. Rendering remains outside the model and no
generated output enters serialization.

Files:
- `src/rich-specials.ts` — Mermaid classification.
- `src/rich-specials.test.ts` — case/whitespace info strings, source fidelity,
  and non-Mermaid fences.

## AC-8 (added): Loss-aware re-projection

Approach: Reproject from the updated source after every explicit source
operation and carry all node/range offsets in JavaScript UTF-16 units. Add
regression coverage for Unicode labels, CRLF adjacent blocks, nested marks,
unknown syntax, and unchanged serialization.

Files:
- `src/rich-markdown.ts`
- `src/rich-specials.ts`
- `src/rich-markdown.test.ts`
- `src/rich-specials.test.ts`

## AC-9 (added): No implicit source reveal

Approach: Keep special blocks source-visible/opaque in the pure model rather
than inventing placeholder text or relying on selection-triggered reveal. A raw
source-position lookup plus explicit source-edit APIs are the only special-block
editing boundary; view widgets can later consume the same nodes.

Files:
- `src/rich-markdown.ts` — opaque special ranges and explicit source-position
  lookup.
- `src/rich-markdown.test.ts` — caret/mapping behavior and no implicit reveal
  assumptions.
