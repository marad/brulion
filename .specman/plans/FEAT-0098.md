## AC-6 (added): Given a successful local same-note or cross-note anchor navigation, when
  the user uses browser Back and Forward, then the route records the local note
  path and anchor, Back restores the prior note/scroll position, and Forward
  restores the anchored heading without changing any Markdown bytes.

Approach: Extend the existing note-route codec with an optional encoded local
anchor while keeping legacy `#/path` routes valid. Make anchored Markdown and
wikilink follows create one browser-history entry, capture the source editor
scroll position in that entry, and handle Back/Forward through the existing
route path so the target heading or prior position is restored without
introducing a second navigation stack. Serialize link-driven anchor switches
with browser-route traversals and invalidate stale async completions before
they can push a route, release route-sync suppression, apply a delayed
scroll-position callback, or lose a requested route while the initial note
listing is still incomplete.

Files:
- `src/note-route.ts` — optional anchor route encoding/decoding.
- `src/note-route.test.ts` — legacy, anchored, and malformed-route coverage.
- `src/main.ts` — anchor-aware route/history synchronization and restoration,
  including serialized stale-navigation guards and retry after incomplete listing.
- `e2e/link-anchors.spec.ts` — real same-note and cross-note Back/Forward checks,
  including in-flight link/traversal, delayed-scroll, and incomplete-listing
  route races.
