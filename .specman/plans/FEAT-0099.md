## AC-1 (added): Given settings JSON with no `focusActiveNote`, an invalid value, `true`,
  or `false`, when settings are normalized and loaded, then missing/invalid
  values become `true`, valid booleans are preserved, and save/load round-trips
  the chosen value through `.brulion.json`.

Approach: Extend the existing `Settings` contract/default/normalizer and reuse
`loadSettings`/`saveSettings`; invalid or absent values fall back to the
opt-in default rather than coercing arbitrary input.

Files:
- `src/settings.ts` — persisted settings field and normalization.
- `src/settings.test.ts` — pure and mocked filesystem round-trip coverage.

## AC-2 (added): Given the Settings modal is open, when it is seeded from either value,
  then a labeled active-note-focus checkbox reflects that value; when the user
  toggles it, then the modal emits `{ focusActiveNote: boolean }` and the live
  host can persist the patch.

Approach: Add one checkbox row to the existing modal, seed it from
`getSettings()`, and emit a partial settings patch on change through the host's
existing update/persist path.

Files:
- `src/settings-modal.ts` — checkbox control and live patch event.
- `src/settings-modal.test.ts` — seed and toggle assertions.

## AC-3 (added): Given the focus preference is enabled and the active note changes from
  one existing note to another, when the sidebar is visible, then the matching
  visible note row receives DOM focus, has the active visual/ARIA state, and is
  the sole roving `tabindex="0"` row.

Approach: Keep tree DOM projection in `ui.ts`: expose a small active-row updater
that refreshes visual/ARIA state and roving tabindex, plus a guarded focus helper
that focuses only a visible matching note row. The main controller callback calls
it only when the announced active path differs from the previous path and the
sidebar is actually open.

Files:
- `src/ui.ts` — active-row projection/focus helper.
- `src/main.ts` — genuine-navigation and collapsed-sidebar guards.
- `src/ui.test.ts` — focus, ARIA, roving-tabindex, and visibility behavior.
- `e2e/active-note-focus.spec.ts` — real navigation/settings browser coverage.

## AC-4 (added): Given the editor or a dialog currently has focus, when a poller repaint
  announces the same active note, then DOM focus stays where it was; given the
  preference is disabled, an active-note change updates visual/ARIA state but
  does not move DOM focus; given the sidebar is collapsed, navigation does not
  force it open or focus a hidden row.

Approach: Separate active-state repaint from the opt-in focus side effect. The
existing render focus-preservation guard remains authoritative for background
rebuilds; main.ts checks the preference and `.sidebar-collapsed` class before
calling the helper, while disabled mode still updates the active row without
calling `.focus()`.

Files:
- `src/ui.ts`, `src/main.ts` — non-stealing focus and collapsed-sidebar guards.
- `src/ui.test.ts` — outside-focus, disabled, and hidden-row cases.
- `e2e/active-note-focus.spec.ts` — live toggle and collapsed sidebar checks.

## AC-5 (added): Given either preference value, when notes are opened, switched, or
  repainted, then no Markdown file is created, modified, or rewritten by the
  focus behavior.

Approach: Keep the feature in DOM/settings glue only and snapshot the OPFS note
set/content around browser navigation; unit tests assert helpers do not call any
filesystem API.

Files:
- `e2e/active-note-focus.spec.ts` — exact Markdown-byte preservation.
- `src/settings.test.ts`, `src/ui.test.ts` — no-I/O pure/DOM coverage.
