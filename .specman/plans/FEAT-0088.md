## AC-8 (added): Given API version 1, when the canonical API contract is inspected, then
  it defines the manifest contract, permission-to-capability mapping, runtime
  constraints, and every supported public method with its parameters, return
  values, limits, and version metadata.

contract. It describes the manifest fields, all five permissions, sandbox and
size/time limits, reusable result types, and the complete commands/editor/notes

examples. `src/extension-api-contract.ts` parses and validates the shape so the
docs renderer and contract tests consume the same source and reject an
incomplete contract early.

## AC-11 (added): Given the canonical API contract, when the authoring kit is built, then
  the browser reference and TypeScript declarations expose the same method
  inventory and signatures, and a contract test fails if a documented public
  method is missing from either generated artifact or the runtime bridge.

Approach: Expose a stable public method inventory from the host-side extension
bridge and compare it with the contract and declaration surface in a
deterministic contract test. The test covers command, editor, and note methods,
manifest permissions, shared type declarations, and representative results, so
adding a runtime method without updating the authoring artifacts fails before
release. Runtime validation and permission enforcement remain in the existing
host.

## AC-12 (added): Given an API method that reads or writes user-owned notes, when its
  reference is read, then it explicitly describes folder-relative markdown
  paths, normalization, external-edit conflict behavior, and whether the
  operation preserves or changes file bytes; the examples demonstrate the
  file-fidelity-safe calling pattern.

Approach: Document that paths are vault-relative POSIX note names normalized to
`.md`, absent reads return empty content/null mtime, writes use optimistic mtime
guards and return conflict instead of clobbering external bytes, create/delete
are non-destructive on clashes or missing files, and moves refuse occupied
destinations while preserving bytes without rewriting links. Add focused safe
read-modify-write and discriminated-result recipes.
