## AC-1 (added): Given staged files with whitespace errors, when the pre-commit gate
  runs, then it exits nonzero and identifies the cached diff error without
  modifying files.

Approach: Make the gate call `git diff --cached --check` and preserve its output;
  keep the pre-commit path fast and read-only.

Files:
- `scripts/workflow-gate.mjs`
- `scripts/workflow-gate.test.mjs`
- `.githooks/pre-commit`
- `package.json`

## AC-2 (added): Given staged implementation/workflow files and a commit message without
  a `Spec: FEAT-NNNN/AC-M` trailer, when the commit-message gate runs, then it
  exits nonzero; given a valid trailer, it exits zero.

Approach: Separate path classification from trailer parsing. Require a trailer
  only when staged paths represent implementation or workflow behavior, and
  expose pure functions so both missing and valid messages are discriminated.

Files:
- `scripts/workflow-gate.mjs`
- `scripts/workflow-gate.test.mjs`
- `.githooks/commit-msg`

## AC-3 (added): Given documentation/spec-only staged files, when the commit-message
  gate runs without a trailer, then it exits zero so process documentation does
  not need a fabricated feature reference.

Approach: Keep documentation/spec paths outside the implementation path
  classifier; a commit may still add a trailer, but it is not required.

Files:
- `scripts/workflow-gate.mjs`
- `scripts/workflow-gate.test.mjs`
- `.githooks/commit-msg`

## AC-4 (added): Given a clean checkout and installed browser dependencies, when the
  `ci` or pre-push gate runs, then it invokes preflight, spec validation,
  workflow tests, Vitest, build, and E2E in order and stops on the first failure.

Approach: Use one ordered command list in the shared Node gate entrypoint; the
  `ci` and `pre-push` modes call the same list. Do not impose a time limit or
  retry a failed command.

Files:
- `scripts/workflow-gate.mjs`
- `scripts/workflow-gate.test.mjs`
- `.githooks/pre-push`
- `package.json`

## AC-5 (added): Given any failed full-gate command, when the gate exits, then it returns
  nonzero with the failed command and captured output and does not run later
  commands as if the gate passed.

Approach: Inject a command runner into a pure ordered executor for tests; stop
  at the first nonzero result and return command/stdout/stderr evidence.

Files:
- `scripts/workflow-gate.mjs`
- `scripts/workflow-gate.test.mjs`

## AC-6 (added): Given a fresh clone, when the opt-in hook installer runs, then Git's
  `core.hooksPath` points to the checked-in `.githooks` directory and the hooks
  delegate to the checked-in gate entrypoint without global configuration.

Approach: Add a small idempotent installer that runs `git config core.hooksPath`
  for the current repository, plus POSIX hook shims that resolve the repository
  root before invoking Node.

## AC-7 (added): Given a pull request or a push to `main`, when GitHub Actions runs, then
  the quality job executes the same checked-in full gate on a clean checkout,
  and the Pages deployment cannot proceed unless the quality job succeeds.

Approach: Add a pull-request/main quality workflow that installs Node and
  Chromium dependencies, then invokes the checked-in `ci` gate. Add the same
  quality job as a prerequisite inside the Pages deployment workflow so a local
  hook bypass cannot deploy.

Files:

## AC-8 (added): Given the gate scripts and hooks, when they are inspected, then no
  substantive subagent receives a hard wall-clock, hard turn, or hard tool
  timeout by default, and local-hook bypass cannot bypass CI.

Approach: Keep timeout policy in the project skills/AGENTS protocol and make the
  gate executor run commands without timeout options. Test that hook shims point
  to the checked-in entrypoint and that CI invokes the same `ci` mode.
