## AC-6 — invalid legacy entries do not poison note listings

Approach: Keep the throwing `notePath` validator unchanged for direct path
arguments. In the host-side `notes.list` loop, validate each app-side entry
independently, omit entries whose normalization or `.brulion` root check fails,
and preserve canonical normalization plus `Set`-based deduplication for valid
entries. Add a regression for mixed legacy paths and retain a direct invalid
`notes.read` rejection. Document the omission in the Authoring Kit source; the
build regenerates the checked-in public artifacts.

Files: `src/extension-host.ts`, `src/extension-host.test.ts`,
`extension-kit/API.md`, `extension-kit/api-contract.json`,
`public/api.md`, `public/api-contract.json`.
