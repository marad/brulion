# Sync plan — FEAT-0089 Extension command icon names

Started: 2026-08-08T20:44:52.068Z
Snapshot state: new
Drift summary: 6 added (whole spec)

## AC-1 (added): Given a command registration with any non-blank icon string that names a
  bundled Lucide icon, when it is accepted, then the command and action carry the
  corresponding host Lucide icon.

Approach: Resolve icon names against the complete Lucide catalog already bundled by Brulion. Keep the extension-facing value as a string, normalize common Lucide name spellings for lookup, and return the matching host-owned IconNode for known names.

Files:
- `src/extension-icons.ts`
- `src/extension-icons.test.ts`
- `src/extension-host.test.ts`

## AC-2 (added): Given a command registration with no, blank, or unavailable icon name,
  when it is accepted, then registration succeeds and the action uses the puzzle
  icon.

Approach: Treat missing, blank, and unknown strings as ordinary metadata rather than invalid command input; resolve them to the existing puzzle fallback without rejecting registration.

Files:
- `src/extension-icons.ts`
- `src/extension-icons.test.ts`
- `src/extension-host.test.ts`

## AC-3 (added): Given a command registration with arbitrary SVG markup or another
  untrusted string, when it crosses the RPC boundary, then it is treated only as
  an icon name and no markup or extension asset is rendered.

Approach: Never interpolate the supplied value into DOM or SVG. Only a host-owned IconNode returned by the Lucide catalog reaches the existing renderers; unknown or markup-looking strings therefore use puzzle.

Files:
- `src/extension-icons.ts`
- `src/extension-icons.test.ts`
- `src/extension-host.test.ts`

## AC-4 (added): Given a pinned extension action, when the action bar renders, then it
  uses the compact icon button shape and retains an accessible label/title.

Approach: Preserve the existing Action/IconNode pipeline and its icon-first compact button rendering. Add a regression assertion through the host action surface rather than introducing a second toolbar path.

Files:
- `src/extension-host.test.ts`
- `src/ui.ts`
- `src/ui.test.ts`

## AC-5 (added): Given a command is registered and invoked, when its icon metadata changes
  or is unavailable, then command execution and extension isolation remain
  unchanged.

Approach: Keep icon resolution pure metadata at registration time; command ids, callbacks, invocation RPC, and per-extension disposal remain unchanged. Exercise invocation with a newly supported icon and an unavailable name.

Files:
- `src/extension-host.test.ts`

## AC-6 (added): Given the authoring declaration is inspected, when a command's icon type
  is read, then it is `string` rather than a finite string-literal union.

Approach: Replace the finite icon-name declaration with the public `string` type and update the machine-readable contract and prose so the kit, browser reference, and runtime semantics agree.
