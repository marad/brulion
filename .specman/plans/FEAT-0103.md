# Sync plan — FEAT-0103 Direction-aware extension editor selection

Started: 2026-08-13T08:50:19.218Z
Snapshot state: new
Drift summary: 6 added (whole spec)

## AC-1 (added): Given an active note with a forward, backward, or collapsed primary
  selection, when an extension with `editor:read` calls `editor.getSelection`,
  then it receives the corresponding `{ anchor, head, text }` with exact raw
  Markdown UTF-16 offsets and the backward direction preserved.

Approach: Keep the public host/bootstrap shape from FEAT-0102 and exercise the
application adapter against CodeMirror's `SelectionRange.anchor` and `head`,
using `from`/`to` only to slice raw source text. Add a focused editor/main
regression test for a reverse selection containing hidden Markdown markers.

Files:
- src/main.ts
- src/extension-host.test.ts
- src/extension-navigation.test.ts
- e2e/extensions.spec.ts (if the existing browser fixture can observe the selection)

## AC-2 (added): Given an extension with `editor:selection`, when it calls
  `editor.setSelection({ anchor, head })` with two in-range integer offsets,
  then the active editor receives that direction-aware selection, focuses, and
  scrolls it into view without changing document text or initiating a save.

Approach: Keep `setSelection` as a selection-only CodeMirror dispatch in the
captured-vault editor capability. Assert the dispatch maps to the requested
anchor/head, focus and scroll flags are requested, and no document-change/save
callback is used.

Files:
- src/main.ts
- src/extension-host.test.ts
- src/editor.test.ts
- e2e/extensions.spec.ts

## AC-3 (added): Given a set-selection request with a negative, fractional, unsafe
  integer, or out-of-document offset, when it crosses the host and active-view
  adapter, then it rejects and neither the editor selection nor the document
  changes; the injected application callback is not invoked for host-invalid
  shapes.

Approach: Reuse the strict wire validator for shape/safe-integer/negative
checks, and keep document-length validation in the captured editor adapter.
Cover each class with discriminating host tests and an adapter boundary test;
never loosen the validator to rely on CodeMirror exceptions.

Files:
- src/extension-host.ts
- src/extension-host.test.ts
- src/main.ts
- src/editor.test.ts

## AC-4 (added): Given a manifest with `editor:read` but not `editor:selection`, when
  it calls `getSelection` and `setSelection`, then the read succeeds and the
  write-like selection control rejects before the editor adapter is called.
  Given `editor:selection` without `editor:read`, `setSelection` remains
  available but `getSelection` remains denied.

Approach: Preserve FEAT-0102's independent permission gates and add a
least-privilege matrix test for both grant combinations, asserting callbacks
are not reached on denied calls.

Files:
- src/extension-host.test.ts
- src/script-manifest.test.ts

## AC-5 (added): Given a selection-control call after the captured vault has been
  detached or replaced, when the extension invokes it, then the stale-vault
  guard rejects before dispatching and cannot move the selection in the new
  vault.

Approach: Bind the adapter to the same root identity and assertActive callback
used by notes/navigation. Add a stale-root test that flips the captured root
before calling setSelection and verifies no dispatch callback occurs.

Files:
- src/main.ts
- src/extension-navigation.test.ts
- src/extension-host.test.ts
- e2e/extensions.spec.ts (if the existing vault-switch fixture supports it)

## AC-6 (added): Given a selected range containing hidden Markdown markers, when an
  extension reads or moves the selection, then offsets and returned text refer
  to the raw document and the operation exposes no decoration, DOM, or
  CodeMirror object.

Approach: Assert the host result contains only bounded primitive fields and the
adapter slices the raw CodeMirror document, not rendered DOM text. Add a
contract/bootstrap assertion that no editor object leaks.

Files:
- src/extension-host.test.ts
- src/extension-runner.test.ts
- src/extension-api-contract.test.ts
- e2e/extensions.spec.ts
