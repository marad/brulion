## Intent

An explicitly enabled extension should be able to inspect and move the primary
selection in the active CodeMirror note without being given CodeMirror, DOM, or
filesystem objects. The public selection must preserve the user's direction,
use raw Markdown UTF-16 offsets, and remain separate from content mutation so a
selection-focused extension cannot silently rewrite note bytes.

## Behavior

`editor.getSelection()` returns `{ anchor, head, text }` for the active primary
selection. `anchor` is the selection origin and `head` is the active end, so a
backward selection keeps `anchor > head`; a collapsed cursor has equal offsets.
Offsets are zero-based JavaScript UTF-16 positions in the raw Markdown
CodeMirror document, and `text` is the source slice between the normalized
selection endpoints. The host continues to gate reads with `editor:read`.

`editor.setSelection({ anchor, head })` is gated independently by
`editor:selection`. The active-view adapter checks both offsets against the
current document length, dispatches only a CodeMirror selection transaction,
scrolls the selected range into view, and focuses the editor. It does not call
or share the content replacement path, does not trigger a document change, and
does not write or autosave the note. An invalid or stale-vault request rejects
before dispatch and leaves the current selection and bytes unchanged.

## Acceptance criteria

- AC-1: Given an active note with a forward, backward, or collapsed primary
  selection, when an extension with `editor:read` calls `editor.getSelection`,
  then it receives the corresponding `{ anchor, head, text }` with exact raw
  Markdown UTF-16 offsets and the backward direction preserved.
- AC-2: Given an extension with `editor:selection`, when it calls
  `editor.setSelection({ anchor, head })` with two in-range integer offsets,
  then the active editor receives that direction-aware selection, focuses, and
  scrolls it into view without changing document text or initiating a save.
- AC-3: Given a set-selection request with a negative, fractional, unsafe
  integer, or out-of-document offset, when it crosses the host and active-view
  adapter, then it rejects and neither the editor selection nor the document
  changes; the injected application callback is not invoked for host-invalid
  shapes.
- AC-4: Given a manifest with `editor:read` but not `editor:selection`, when
  it calls `getSelection` and `setSelection`, then the read succeeds and the
  write-like selection control rejects before the editor adapter is called.
  Given `editor:selection` without `editor:read`, `setSelection` remains
  available but `getSelection` remains denied.
- AC-5: Given a selection-control call after the captured vault has been
  detached or replaced, when the extension invokes it, then the stale-vault
  guard rejects before dispatching and cannot move the selection in the new
  vault.
- AC-6: Given a selected range containing hidden Markdown markers, when an
  extension reads or moves the selection, then offsets and returned text refer
  to the raw document and the operation exposes no decoration, DOM, or
  CodeMirror object.

## Out of scope

- Replacing or inserting content, clipboard access, multiple-selection models,
  selection-change events, automatic triggers, or custom extension UI.
- Notification and dialog rendering; those are FEAT-0104 and FEAT-0105.
- Changing Markdown bytes, file paths, mtime guards, or the extension API
  version.
