# M41 — Full extension workbench and authoring kit

M41 turns the M39 runtime slice into an authoring surface that a person or an
LLM agent can use without manually constructing `.brulion/scripts/` folders.
The workbench is a separate Brulion window, but it does not depend on a
window-to-window session: every window reads and writes the shared vault through
its own File System Access handle, with the filesystem remaining the source of
truth.

## Design spine

- The existing M39 inline editor is retired in favor of a dedicated workbench
  window. Notes remain available in another Brulion window.
- A script is a small file tree, not a single source string: `manifest.json`,
  `main.js`, and supported JavaScript/JSON companions open in real tabs.
- One dropdown selects the extension; the sidebar does not duplicate extension
  management or use static chevrons that falsely imply collapsible sections.
- Creation uses focused dialogs with local validation feedback and produces a
  safe disabled scaffold. Enablement/removal remain in the separate extension
  manager and are persisted in the vault settings.
- Every write keeps the existing mtime guard. A second window or an external
  agent can edit the same file without silent clobbering.
- The Authoring Kit is one versioned source containing the template, API types,
  examples, `AGENTS.md`, the LLM skill, and a ready-to-use prompt.
- Command icons use an allowlisted Lucide name over the JSON-like RPC boundary;
  missing or invalid names fall back to `puzzle`.

## Phases

- [ ] **P0 — Workbench contract and separate-window architecture**
  Define the window lifecycle, vault restoration, filesystem ownership, refresh
  semantics, and the no-IPC correctness rule. Produce the excavation architecture
  artifact and acceptance criteria before implementation.
- [ ] **P1 — Multi-file workbench shell**
  Open the workbench in a separate window with an extension dropdown, file list,
  real tabs, CodeMirror editors, close/reopen behavior, and clear handling of a
  missing vault permission.
- [ ] **P2 — Extension creation and file operations**
  Create a validated disabled scaffold through a focused dialog; support
  manifest/source/companion-file create, read, save, rename, and delete with
  conflict guards and local creation diagnostics. Extension enablement/removal
  stays in the existing manager.
- [ ] **P3 — Authoring Kit for humans and LLM agents**
  Ship the versioned template, `brulion-extension.d.ts`, examples, API reference,
  `AGENTS.md`, an LLM skill, and a prompt; make the kit copyable/downloadable
  from the workbench and usable directly from the repository.
- [ ] **P4 — Command icon API and toolbar correction**
  Add `icon?: string` to command registration, map only allowlisted Lucide names,
  use `puzzle` by default, and ensure pinned extension actions remain compact.
- [ ] **P5 — Cross-window freshness and release validation**
  Refresh each window from the filesystem on attach/focus/workbench open and on a
  portable fallback cadence; cover invalidation, conflict, reload, browser E2E,
  and agent-authored extension scenarios. FSO optimization remains M40.

## Done =

A user can open the workbench in a separate window, select an extension from a
dropdown, create one through a focused dialog, edit its manifest and multiple
source files in real tabs, and save without silently overwriting a change from
another window. The user can then explicitly enable it through the separate
extension manager and run a command with a compact Lucide-backed toolbar action. A user or LLM agent can follow the bundled
Authoring Kit to produce a valid extension without reverse-engineering the API or
manually creating the `.brulion/scripts/` directory. Independent Brulion windows
converge by rereading the shared vault; no inter-window message bus is required
for correctness.

## Out of scope

- arbitrary SVG icon markup or custom icon files;
- TypeScript execution/transpilation or package installation;
- network imports, timers, background execution, or an in-app LLM;
- FileSystemObserver as the baseline watcher (scheduled separately as M40).
