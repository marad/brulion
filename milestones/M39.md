# M39 — Local JavaScript extensions

M39 turns the FEAT-0081 sandbox/RPC spike into a file-faithful extension system.
The extension folder is part of the user's workspace, but extension code is
untrusted and is never run in Brulion's main context.

## Design spine

- Scripts live under `.brulion/scripts/<id>/`; this keeps implementation metadata
  next to the vault without polluting the note tree or the markdown file set.
- The MVP is JavaScript-only. A manifest names the entry file and explicitly
  declares the capabilities a later host may grant.
- Every script write uses a single-file mtime guard. The app never silently
  overwrites an external edit.
- The editor is a reusable CodeMirror surface used by the local Extensions workbench.
- FEAT-0081's opaque-origin iframe, source/nonce checks, JSON-like wire values,
  timeout, and disposal rules remain mandatory when execution is added.

### P1 — Script storage, manifest validation, and JavaScript editor

**P1/P2 Done =** a valid `.brulion/scripts/<id>/manifest.json` and `main.js` can
be discovered, read, edited, saved with an mtime conflict guard, explicitly
enabled, and deleted through tested host functions; invalid/traversal paths and
unsupported manifests are rejected without touching user files. Enabled ESM
scripts run in an opaque-origin `allow-scripts` iframe through the
permission-gated host API, and namespaced commands appear in the existing
palette/action bar. The reusable CodeMirror JavaScript editor loads text without
reporting a user change, reports real edits, exposes current text, and passes the
full TypeScript/Vitest suite.
