# M46 — Extension interaction API

M46 extends local JavaScript extensions from editor text and note/navigation
operations to deliberate interaction with the active editor and the user. The
host owns rendering, focus, modal lifecycle, and permissions; extensions receive
only bounded JSON-like values across the existing sandbox/RPC boundary.

## Design spine

- **Direction-aware selection.** `editor.getSelection()` returns the primary
  selection as `{ anchor, head, text }`. `anchor` is where selection began and
  `head` is the active cursor position; a collapsed cursor has equal values.
  Offsets are zero-based UTF-16 positions in the raw markdown document. The
  public contract does not expose CodeMirror objects, DOM coordinates, or a
  second/multiple-selection model.
- **Selection control without content writes.** `editor.setSelection({ anchor,
  head })` moves the active selection, focuses the editor, and brings it into
  view. It never changes markdown bytes; content mutation remains behind the
  existing editor-write capability.
- **One message language.** Notifications and dialogs share a
  `MessageContent`/`MessagePart` contract: plain text, `strong`, and `code`
  fragments. A `\n` in a fragment is a semantic line break. The host renderer
  inserts safe text and `<br>` nodes; extension HTML, Markdown parsing, custom
  CSS, links, and nested markup never cross the boundary.
- **Host-owned in-app notifications.** `notifications.show()` is a
  non-blocking, permission-gated toast with `info`, `success`, `warning`, and
  `error` levels. It never steals focus or exposes action callbacks; the host
  controls dismissal, queue/rate limits, and extension attribution.
- **Host-owned dialogs.** `dialogs.alert()`, `dialogs.confirm()`, and
  `dialogs.prompt()` reuse the app's modal/focus conventions. Messages use the
  shared renderer, every visible button has an extension-supplied plain-text
  label, prompt cancellation is distinct from an accepted empty string, and
  multiline prompting is explicit.
- **Interactive lifecycle is bounded.** Dialog calls use an RPC timeout suitable
  for human interaction rather than the ordinary short capability timeout.
  Dialogs are serialized with the host modal surface, restore focus, and settle
  deterministically when an extension is disposed or its vault becomes stale.

## Phases

- [ ] **P0 — Interaction contract and permission boundary** (`FEAT-0102`)
  Add the direction-aware selection, shared message, notification, and dialog
  contracts to the host allowlist, permissions, sandbox bootstrap, declarations,
  and machine-readable API contract. Define bounded values, cancellation,
  disposal, and interactive timeout behavior before UI bodies exist.

  **Done =** the host and sandbox agree on the complete additive interaction
  method inventory, permissions fail closed, every wire value has explicit
  bounds, and the Authoring Kit contract tests reject drift.

- [ ] **P1 — Direction-aware editor selection** (`FEAT-0103`)
  Implement `editor.getSelection()` and `editor.setSelection()` over the active
  CodeMirror editor, including UTF-16 bounds validation, collapsed cursors,
  reverse selections, focus/scroll behavior, stale-vault checks, and the rule
  that selection control never writes markdown.

  **Done =** an explicitly permitted extension can read and set the primary
  selection in either direction, receives the raw selected text, and cannot use
  the capability to mutate note bytes; unit and browser coverage discriminate
  invalid and out-of-range positions.

- [ ] **P2 — Shared formatted messages and in-app notifications** (`FEAT-0104`)
  Build the host-owned message renderer and expose `notifications.show()` with
  levels, bounded plain/strong/code fragments, semantic newlines, attribution,
  non-focus-stealing behavior, and serialized dismissal/rate handling.

  **Done =** an enabled extension with the notification permission can show a
  safe formatted toast, while HTML/unsupported values, oversized payloads, and
  missing permissions are rejected without affecting the notes editor.

- [ ] **P3 — Formatted dialogs and interactive RPC** (`FEAT-0105`)
  Expose formatted `alert`, `confirm`, and `prompt` dialogs with per-button
  labels, initial values, placeholders, optional multiline input, cancellation
  semantics, modal queuing, focus restoration, disposal cancellation, and a
  human-scale RPC timeout. Keep the existing app dialog and conflict/modal
  boundaries authoritative.

  **Done =** a command-invoked extension can ask for acknowledgement, a
  yes/no decision, or text, receives unambiguous results, and cannot inject
  markup or leave a pending modal/RPC call after it is disabled or detached.

- [ ] **P4 — Authoring Kit and browser validation** (`FEAT-0106`)
  Update the declarations, API guide, contract reference, examples, diagnostics,
  and static artifacts. Cover the host boundary, sandbox bootstrap, permissions,
  selection direction, formatted rendering, dialog lifecycle, timeout, and
  real Chromium extension flows.

  **Done =** a user or LLM agent can author an extension against the published
  contract, the checked-in and deployed references agree, and the complete
  interaction surface passes unit, build, and browser validation.

## Done =

An explicitly enabled extension can read and move the active primary selection,
show a safe formatted in-app notification, and ask the user for acknowledgement,
a decision, or bounded text through a host-owned dialog. Selection direction,
newline rendering, button labels, cancellation, permissions, disposal, and
human-scale interaction timeouts are documented and tested across the sandbox
boundary without exposing DOM, CodeMirror, filesystem handles, or system
notification capabilities.

## Out of scope

- system/OS notifications or browser notification permission prompts;
- a `choose()`/picker capability (the existing picker integration is a separate
  milestone);
- automatic extension events, selection/note-change subscriptions, timers,
  background execution, or startup-triggered user prompts;
- custom extension UI, arbitrary HTML/CSS, links/actions inside messages,
  clipboard access, DOM access, or filesystem handles;
- TypeScript execution, packages, network imports, or weakening existing mtime
  and sandbox boundaries.
