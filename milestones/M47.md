# M47 — Rich Markdown editor in CodeMirror

M47 changes the editing model without changing the file model. Brulion continues to
read and write ordinary Markdown files, but the primary editor no longer treats
Markdown source as its visible document. It becomes a rich-text projection backed
by a loss-aware Markdown source map, while CodeMirror remains the editor engine.

M46 is a separate extension-API workstream being developed in parallel. M47 must
preserve the public editor/API boundaries that M46 defines (especially raw
Markdown text and UTF-16 source positions), but M46 is not a reason to delay this
editor work or a dependency on its implementation order.

## Design spine

- **CodeMirror stays.** The existing editor engine, history, selection, keymaps,
  Vim integration, DOM-free tests, and editor extensions remain the foundation.
  This is a model change, not a ProseMirror/Tiptap migration.
- **The visible document is rich text.** The CodeMirror document contains the
  text the user sees. Marks and blocks live in a CodeMirror state field/model;
  Markdown delimiters are not invisible characters that the caret must step over.
  A source map relates visible positions and rich nodes to their Markdown source
  ranges.
- **Markdown remains the file format and source of truth.** Loading parses the
  existing file into the rich projection. Saving serializes the model back to
  Markdown. An untouched note round-trips byte-for-byte; untouched source spans
  keep their original spelling, whitespace, delimiter choice, and ordering.
  A user operation may rewrite only the source span it actually changes, using a
  documented canonical form for newly created syntax.
- **Markdown input is a first-class editing path.** Users may still type
  Markdown. A pending marker sequence can remain visible while it is incomplete;
  once a construct reaches its boundary, one transaction removes the delimiters
  from the visible projection and creates the corresponding rich mark/block.
  `**hello** ` must therefore become visible bold `hello` followed by a normal
  space, while serialization retains `**hello** ` in the file.
- **Boundaries are explicit.** A terminating space is the primary boundary for
  inline marks and line prefixes. Enter, Tab, completed closing constructs, and
  blur/save flush pending input where appropriate, so a closing marker at the end
  of a note cannot remain accidentally raw forever. Each construct gets its own
  boundary rule; a generic character replacement pass is not sufficient.
- **Unknown and opaque syntax is safe.** Markdown the model does not understand
  is never silently discarded. Unsupported material remains an opaque/raw island
  with an explicit source-editing affordance. Frontmatter stays opaque and
  byte-preserving; Mermaid, tables, and code blocks have deliberate source/edit
  behavior rather than accidental cursor-line reveal.
- **One user action, one undo unit.** A conversion such as `**hello** ` → bold
  `hello ` is one CodeMirror history transaction. Caret and selection mapping are
  based on the visible projection, while source offsets are derived through the
  map rather than exposed as hidden caret stops.
- **Raw Markdown APIs remain compatible.** Storage, conflict detection, and the
  extension API consume the current serialized Markdown snapshot. Internal rich
  positions are translated at the boundary; public raw-source positions defined
  by M46 are not silently changed into visible-text positions.

## Phases

- [x] **P0 — Rich document contract and Markdown behavior matrix** (`FEAT-0107`)
  Define the rich model, source-map invariants, visible/source position rules,
  serialization ownership, and a behavior matrix for every current Markdown
  construct: paragraphs, headings, bold, italic, inline code, blockquotes,
  unordered/ordered lists, links, wikilinks, fenced code, tables, frontmatter,
  Mermaid, and unknown syntax. For each construct specify recognition, the
  temporary pending state, the boundary that commits it, caret/Enter behavior,
  source editing, and round-trip rules.

  **Done =** the matrix and contracts are specific enough to write discriminating
  tests, the lossless/changed-span policy is explicit, and no construct relies on
  an unrecorded reveal-on-cursor exception.

- [x] **P1 — Loss-aware import and visible rich projection** (`FEAT-0109`)
  Build the CodeMirror state/model layer that parses an existing Markdown note into
  visible text plus rich marks/blocks and source mappings. Start with paragraphs,
  headings, inline marks, blockquotes, lists, inline code, and opaque fallback
  regions. Loading a file must not rewrite it, and the projection must support
  deterministic visible-position/source-position mapping.

  **Done =** existing notes render as rich text without hidden Markdown caret stops,
  unchanged content serializes byte-for-byte, unknown syntax survives as a safe
  raw region, and unit tests cover nested marks, multiline blocks, Unicode, and
  source-map boundary positions.

- [x] **P2 — Inline Markdown input rules and formatting model** (`FEAT-0110`)
  Add user-typing conversion for `**…** ` / `__…__ `, `*…* ` / `_…_ `, and
  `` `…` `` with the agreed boundary behavior. Add the equivalent rich model
  operations behind Ctrl/Cmd shortcuts and selection formatting, preserving the
  marker spelling for imported content and using the canonical form only for new
  syntax. Incomplete or literal markers remain editable instead of being guessed
  away.

  **Done =** typing `**hello** ` produces visible bold text plus an unformatted
  trailing space in one undo step; headings/blocks are not accidentally parsed as
  inline marks; nested marks, empty spans, escaped markers, URLs, punctuation,
  Enter/Tab, EOF, blur, and undo/redo have discriminating coverage.

- [ ] **P3 — Block input rules and rich block editing** (`FEAT-0111`)
  Convert line prefixes such as `# `, `## `, `> `, `* `, and `- ` at their
  Markdown boundaries into headings, quotes, and list blocks. Rework Enter,
  Backspace, continuation, exit, indentation, and heading-level commands against
  the rich model rather than against hidden source characters. Define ordered-list
  behavior explicitly in P0 and implement it consistently if included in the
  matrix; otherwise preserve it as an opaque/plain construct without data loss.

  **Done =** typing a completed line prefix produces the intended rich block with
  correct caret placement, list/quote continuation and exit are predictable, rich
  formatting commands no longer insert raw markers into the visible document, and
  all block source round-trips exactly when untouched.

- [ ] **P4 — Links, code fences, tables, frontmatter, and Mermaid** (`FEAT-0112`)
  Move the remaining current renderers onto the new model boundary. Complete
  Markdown links and wikilinks into rich link nodes while keeping target editing
  deliberate; enter and leave fenced code blocks through explicit fence/Enter
  rules; define table completion/editing; keep frontmatter opaque and expandable;
  and keep Mermaid as a rendered block with a safe source-editing path. No
  construct may depend on revealing raw syntax merely because the caret entered it.

  **Done =** each supported special construct has a documented rich or opaque
  representation, a deliberate way to edit its source, correct navigation/render
  behavior, and byte-preserving tests for loaded and newly typed examples.

- [ ] **P5 — Loss-aware serialization and note-controller integration** (`FEAT-0113`)
  Replace direct `view.state.doc` Markdown reads with an editor document boundary
  that provides the current serialized Markdown snapshot. Integrate autosave,
  flush, note switching, lazy note creation, rename/move, external refresh, and
  conflict handling. Compare dirty/conflict state using serialized source, and
  preserve visible caret/viewport anchors when external Markdown is reparsed.

  **Done =** every existing storage path saves the correct Markdown, an untouched
  file is byte-identical, only intended changed spans are rewritten, external
  refresh and conflicts never lose rich edits, and note-controller tests cover
  source/model divergence and stale-write guards.

- [ ] **P6 — Selection, clipboard, commands, Vim, and extension compatibility** (`FEAT-0114`)
  Adapt selection toolbar, slash commands, copy/cut, paste, link autocomplete,
  heading anchors, and the M22 boundary-fidelity behavior to visible rich
  selections. Preserve raw Markdown semantics for the extension API, including
  M46's direction-aware source positions, by translating through the source map.
  Audit opt-in Vim mode over the visible projection and keep source editing as an
  explicit mode rather than reintroducing hidden-marker motions.

  **Done =** visible selections format and copy/paste predictably, internal copies
  retain the intended Markdown/rich meaning, extension reads/writes remain
  source-compatible, Vim either works over visible text or has an explicit tested
  limitation, and no integration reintroduces hidden syntax as normal caret text.

- [ ] **P7 — Migration cleanup and full browser validation** (`FEAT-0115`)
  Remove or retire the old raw-Markdown decoration paths that are superseded by
  the rich model, keep CodeMirror-only workbench/diff editors independent, and
  validate realistic editing flows in Chromium/OPFS: typed conversions, existing
  notes, reloads, conflicts, links, special blocks, source editing, undo, and
  byte fidelity. Keep external `text/html` clipboard interoperability separate
  unless the matrix proves it is required for the core editor contract.

  **Done =** the main editor uses one coherent rich projection, obsolete hidden
  marker machinery is no longer load-bearing, full unit/build/E2E validation passes,
  and representative notes remain byte-faithful through load/edit/save/reload.

## Done =

The main Brulion editor feels like a rich-text editor while Markdown remains the
portable file format. Existing Markdown opens as rich content; typing Markdown
markers such as `**hello** ` and `# ` converts them at explicit boundaries; marks,
blocks, links, and special constructs have deliberate editing rules; unknown
syntax is safe; and saving never silently normalizes or drops unrelated source.
CodeMirror, FSA storage, conflicts, extension boundaries, and the M46 raw-source
contract remain intact. The old hidden-Markdown caret model is no longer the
foundation of the editor.

## Out of scope

- Replacing CodeMirror with ProseMirror, Tiptap, or another editor engine.
- A general Markdown reformatter or whole-document canonicalization pass.
- Silent deletion of unsupported Markdown, HTML, frontmatter, or future syntax.
- A full structured frontmatter form or interpretation of metadata fields.
- Arbitrary custom extension UI, DOM exposure, or a new storage/index sidecar.
- External `text/html` clipboard interoperability and HTML-to-Markdown paste as a
  requirement of the first rich-model cut; these remain a coupled follow-up unless
  the P0 behavior matrix demonstrates that the core editor cannot be usable without
  them.
- Changes to FSA permissions, vault identity, sync, or note-file ownership.
