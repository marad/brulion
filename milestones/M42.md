# M42 — Extension UX, diagnostics, and browser validation

M42 is the former P3 of M39. It follows the runtime slice rather than keeping
settings polish and release hardening inside the milestone that established the
sandbox and host boundary.

## Phase ledger

- **Current phase:** FEAT-0083 maintenance correction — resilient extension note listing (complete).
- **Last completed gate:** Targeted and full Vitest, workflow tests, production build, `specman validate --strict`, `specman verify FEAT-0083`, review pass, and sealed FEAT-0083 snapshot all passed; the worktree is clean and FEAT-0083 is `in-sync`.
- **Next action:** Resume M42 P0 — richer extension settings UX.

## Phases

- [ ] **P0 — Richer extension settings UX**
  Make extension discovery, enable/disable state, removal, and current status
  clear and manageable without relying on the editor surface.
- [ ] **P1 — User-facing diagnostics**
  Surface actionable diagnostics for invalid manifests, capability/permission
  problems, source or load failures, and extension reload state without taking
  down unrelated extensions or the notes editor.
- [ ] **P2 — Full browser validation**
  Cover the real Chromium/FSA/OPFS paths for discovery, permissions, writes,
  mtime conflicts, sandbox execution, capability calls, command registration,
  and the settings/diagnostic flows. Keep the native picker and permission
  prompt as the explicitly manual checks.

## Done =

A user can manage local extensions through a clear settings surface, understand
and act on extension failures or reload status, and the complete M39 runtime
slice is covered by browser tests running against real Chromium filesystem
handles and the sandbox boundary.

## Out of scope

- New extension capabilities or a broader runtime API.
- TypeScript execution, package installation, network imports, or an in-app LLM.
- Replacing the filesystem as the source of truth or weakening mtime guards.
