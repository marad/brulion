# M44 — Daily-use polish and agent-readable API docs

M44 packages four small observations from real use and extension authoring. It is
UI/editor/docs behavior only: the filesystem remains the source of truth, and no
phase may rewrite markdown bytes merely to make the view more convenient.

## Design spine

- **Anchor links are an audit, not a second implementation.** M32/FEAT-0061
  already supports an optional section anchor on local Markdown links and
  wikilinks. The first phase must reproduce the reported standard Markdown form
  and identify a real gap before changing code.
- **Active-note focus is a vault preference.** The setting belongs in the existing
  `.brulion.json` settings model so it travels with the vault, defaults to on,
  and can be turned off when programmatic focus is distracting. The visual active
  state and ARIA state remain correct either way.
- **Focus follows genuine navigation, not background refresh.** A poller/list
  repaint with the same active note must never take focus away from the editor or
  a dialog. A collapsed sidebar stays collapsed; the preference does not silently
  change that separate choice.
- **Headings use a quiet size/weight hierarchy.** The initial target is H1 at
  about `1.35em`, H2 at about `1.15em`, and H3–H6 at body size (`1em`) with bold
  weight. Color and indentation are deliberately not added in the first cut:
  they add theme and layout noise without solving the reported size problem.
- **API documentation is static-first for agents.** The interactive `api.html`
  page may keep JavaScript for search, generated method cards, and copy helpers,
  but its useful agent hand-off must be available without executing JavaScript.
  Publish `/api.md`, `/api-contract.json`, and `/brulion-extension.d.ts` from the
  existing Authoring Kit sources, and link/instruct from the static page shell.

## Phases

- [x] **P0 — Markdown anchor compatibility audit**
  Reproduce `[text](note.md#section-title)` and `[text](#section-title)` with the
  existing M32 follow/scroll path, plus an external URL whose `#fragment` must stay
  external. If the exact report exposes a gap, specify and fix the smallest layer
  responsible; otherwise add only the discriminating regression coverage needed
  to prove the behavior is already intact.

  **Done =** the reported Markdown-link forms resolve to the intended note and
  heading (or same-note heading), external fragments remain untouched, missing
  headings do not error, and no note bytes are written by navigation.

- [x] **P1 — Togglable active-note sidebar focus**
  Add a `focusActiveNote` boolean to the vault settings model, normalized and
  persisted through `.brulion.json`, with the default enabled. Surface it in the
  Settings modal. When enabled, a genuine active-note change focuses the matching
  visible sidebar row and lets the browser reveal that row in the scrollable tree;
  disabled mode keeps the current visual/ARIA active state but does not move DOM
  focus. Do not focus on same-note poller repaints, do not force a collapsed sidebar
  open, and keep the tree's roving-tabindex contract valid after a focus move.

  **Done =** the setting applies on load and live, survives reload, can be toggled
  in Settings, focuses the active row only on genuine navigation, and leaves note
  bytes unchanged in both modes.

- [x] **P2 — Compact heading hierarchy**
  Replace the current oversized heading scale with the design-spine target: H1
  and H2 remain visibly distinct but modestly larger than body text, while H3–H6
  are body-sized bold text. Verify the result with the existing base text-size
  setting and both color themes; rendering remains decoration-only.

  **Done =** headings have the compact hierarchy in the editor, remain
  distinguishable from ordinary bold text where intended, scale with the user's
  base text size, and all original markdown bytes remain unchanged.

- [x] **P3 — Static API documentation for agents**
  Make `api.html` useful as a static hand-off even when its enhancement script is
  not executed: include a visible instruction pointing agents to the raw docs.
  Deploy `api.md` as the human-readable Markdown guide, `api-contract.json` as
  the authoritative machine-readable contract, and `brulion-extension.d.ts` as
  the editor/type-hint surface. Derive or copy these files from the existing
  `extension-kit/` sources during the build and test that the deployed artifacts
  cannot silently drift from them.

  **Done =** fetching the static artifacts returns the current API guidance,
  contract, and declarations without JavaScript; the API page contains a direct
  agent instruction/link in its static HTML; disabling JavaScript still leaves
  that hand-off usable; and the interactive reference remains an optional
  enhancement rather than the only place where the API exists.

## Done =

The exact reported Markdown anchor behavior is covered without duplicating M32;
users can choose whether the sidebar follows the active note with programmatic
focus; the editor's H1–H6 hierarchy is compact enough for headings to be useful in
daily notes; and agents can fetch the API reference and contract as static files.
Unit/e2e coverage is discriminating, all active specs are verified and sealed, and
the milestone is deployed and reviewed live.

## Out of scope

- Replacing or broadening the existing link/path/heading-slug contract without a
  reproduced requirement.
- A table of contents, heading outline, automatic heading navigation, or new
  heading syntax.
- Custom per-heading colors, indentation, margins, or a full typography redesign.
- Any serialization round-trip, metadata sidecar, or other change to user-owned
  `.md` files.
- A separately hand-maintained API reference that can drift from the Authoring
  Kit contract.
